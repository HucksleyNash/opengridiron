## Affected Pages/Routes

- `/pools` — weekly overview, inferred week, per-entry completion, and automatic missing-season import.
- `/pools/:poolId/weeks/:week` — winner, loser, and confidence pick workspaces across active, inactive, locked, empty, stale, and repair states.
- `GET /api/v1/pools/overview` — bootstrap state, schedule freshness, active-entry defaults, and completion counts.
- `GET /api/v1/pools/{poolId}/weeks/{week}?entry_id={entryId}` — canonical schedule, eligibility, recommendations, locks, findings, and card version.
- `PUT /api/v1/entries/{entryId}/weeks/{week}/picks` — atomic full-card draft replacement, validation, version conflicts, and idempotent retry.
- `POST /api/v1/sync/nflverse/schedule?season={season}` — missing/scheduled/retry triggers, full-season reconciliation, collision rollback, and sanitized errors.

## Key Interactions to Verify

- Open Pools with no local season, observe one automatic import, then see the inferred week without reloading.
- Open Pools with ready or stale cached games and confirm the page remains usable during refresh failure.
- Navigate previous/next weeks and confirm background refreshes never override the chosen week.
- Switch pool entries and confirm picks, completion, eligibility, versions, and autosave state never leak across entries.
- Make winner and loser selections, including multi-pick slots, used teams, blocked teams, and both lock modes.
- Complete a confidence card, apply the suggested card, edit selections, move weights with the keyboard, and review missing requirements.
- Edit rapidly while a save is in flight and confirm only the latest pending card is sent after the first request succeeds.
- Open the same entry/week in two tabs, create a version conflict, and reapply only still-unlocked attempted changes.
- Let kickoff pass while the page is open and confirm the server preserves the canonical locked pick.
- Open an inactive entry and a legacy `needs_repair` card; confirm read-only state and exact repair findings.
- Use schedule troubleshooting after a safe import error without exposing local paths, raw upstream bodies, or exception text.

## Edge Cases

- No season games, empty selected week, postseason boundary, overlapping source weeks, postponed game, and completed season.
- nflverse rows for `REG`, `WC`, `DIV`, `CON`, and `SB`; missing odds; preferred and fallback keys; source-key collision.
- January/February scheduler resolves the previous NFL season; Friday refresh runs inside the 96-hour window.
- Invalid custom confidence weight count, duplicate weights, duplicate teams, foreign game/team, null game, and moved-out-of-week pick.
- Incomplete drafts save successfully; invalid cards roll back without incrementing the durable version.
- Identical stale retry returns success; different stale card returns `409`; edits to different weeks do not conflict.
- Slow connection, offline save, rapid repeated controls, navigation during a request, browser reload, and mobile viewport.
- Alembic revision `0001` database containing normal and malformed pool picks upgrades without deletion and downgrades on a disposable copy.

## Critical Paths

- Missing schedule -> automatic season import -> overview -> pool week -> pick -> autosave -> reload with the same canonical card.
- Two SQLite sessions submit version N -> exactly one commits -> loser receives canonical `409` -> database has one valid card.
- Schedule refresh identifies a moved game -> stable identity is preserved -> linked pick becomes an explicit repair state when its source week changes.
- Schedule identity collision -> full refresh rolls back -> previous schedule and every saved pick remain intact -> user sees troubleshooting guidance.
- Confidence suggestions -> complete card -> unique full weight set -> atomic weight swap -> `complete` state.
- Kickoff passage -> monotonic `locked_at` -> later schedule correction cannot reopen or change the pick.
